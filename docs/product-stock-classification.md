# Produto com ou sem consumo de estoque

A migration `20261031003000_require_product_recipe_for_consumption` mantém produtos existentes e novos como **Consome materiais** por padrão. A opção **Sem consumo de estoque**, apropriada para produtos digitais ou sem insumos, é uma classificação explícita no produto. O banco rejeita essa classificação enquanto houver componentes na receita base ou nas receitas de variações ativas; variações inativas são preservadas para histórico. Uma edição feita por cliente legado da RPC v2 volta a classificar a versão como consumo de materiais, por segurança. A RPC v3 grava produto, classificação e idempotência numa única transação; reenvios antigos não alteram uma classificação posterior.

A classificação é congelada no snapshot de cada item de pedido e orçamento. Produto que consome materiais precisa de receita efetiva (base ou própria da variação selecionada) ao criar pedido ou orçamento. Serviço manual continua sem consumo. A aprovação pública copia o snapshot e segue para o rastreio; não dá baixa nesse momento.

Antes de mudar para **Em Produção** ou diretamente para **Concluído**, o banco também verifica pedidos antigos que não têm receita e não foram explicitamente classificados como sem estoque. A transição é rejeitada sem movimentos, execução de consumo ou mudança de status; editar o catálogo não reescreve esses snapshots. É necessário revisar e, quando apropriado, recriar o pedido/orçamento. Pedidos já processados não são corrigidos retroativamente: conferir separadamente se os movimentos existentes refletem a operação. Quando um pedido realmente não tem insumos, a execução é registrada como processada sem baixa de materiais, e a interface não afirma que houve movimento.
