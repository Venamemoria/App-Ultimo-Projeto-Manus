# API de vendas públicas

RPCs PostgreSQL expostas pelo schema `public` (arguments nomeados como no SQL). Funções de mutação interna usam `SECURITY DEFINER`, `search_path = ''` e verificam identidade/role no servidor. Números monetários são retornados como `text` para preservar escala decimal. As projeções públicas não concedem acesso anônimo direto às tabelas operacionais; leituras autenticadas dependem das políticas RLS e das views allowlist.

## Orçamentos

- `vm_create_quote(p_organization_id uuid, p_data jsonb, p_items jsonb, p_valid_until date, p_terms text DEFAULT NULL, p_nonce uuid DEFAULT NULL, p_parent_quote_id uuid DEFAULT NULL) RETURNS TABLE(quote_id uuid, public_token uuid, status text, status_version text, valid_until date, subtotal text, discount_amount text, shipping_amount text, total_amount text)`. Apenas `authenticated` com papel `owner`, `admin` ou `finance`. Emite quote congelada; retorna token de cópia pública, status inicial `Sent` e totais.
- `vm_revise_quote(p_organization_id uuid, p_quote_id uuid, p_data jsonb, p_items jsonb, p_valid_until date, p_terms text DEFAULT NULL, p_nonce uuid DEFAULT NULL) RETURNS TABLE(quote_id uuid, public_token uuid, status text, status_version text, valid_until date, subtotal text, discount_amount text, shipping_amount text, total_amount text)`. Mesmo acesso da criação; emite nova revisão e revoga a anterior atomicamente.
- `vm_revoke_quote(p_organization_id uuid, p_quote_id uuid, p_reason text, p_nonce uuid DEFAULT NULL) RETURNS TABLE(quote_id uuid, status text, status_version text, revoked_at timestamptz)`. Apenas owner/admin/finance autenticados; orçamento aprovado não pode ser revogado.
- `vm_list_quotes(p_organization_id uuid, p_cursor_created_at timestamptz DEFAULT NULL, p_cursor_quote_id uuid DEFAULT NULL, p_limit integer DEFAULT 40) RETURNS TABLE(quote_id uuid, public_token uuid, client_name_snapshot text, title text, status text, valid_until date, subtotal text, discount_amount text, shipping_amount text, total_amount text, currency text, accepted_order_id uuid, created_at timestamptz, revoked_at timestamptz, accepted_at timestamptz, parent_quote_id uuid)`. Somente `authenticated` com papel owner/admin/finance nessa organização; sem SELECT direto. `p_limit` permitido de 1 a 100. Cursor exige ambos os campos ou nenhum; paginação keyset descendente `(created_at,id)`, sem OFFSET. O token só é devolvido a usuários autorizados para copiar/compartilhar. A allowlist não contém email, telefone, endereço, identificadores fiscais, snapshots de contato, notas internas, dados de materiais/receita, custos ou margens.
- `vm_get_quote_admin(p_organization_id uuid, p_quote_id uuid) RETURNS jsonb`. Somente `authenticated` com papel owner/admin/finance na organização; retorna `NULL` para orçamento inexistente ou pertencente a outro tenant. Projeção de revisão estritamente allowlisted: objeto superior `quote_id`, `status`, `parent_quote_id`, `valid_until`, `terms`, `data` e `items`; `data` contém somente `client_id`, `title`, `order_date`, `production_date`, `delivery_date`, `responsible_membership_id`, `public_notes`, `internal_notes`, `discount_type`, `discount_value` e `shipping_amount`. Itens são ordenados por posição e incluem somente campos comerciais permitidos; `unit_price` é `null` para preço de catálogo e texto para preço manual/sobrescrito. Não expõe snapshots de contato/CPF/endereço/contato, custo unitário, materiais ou receita. A função exige identidade e role JWT `authenticated`, além do papel da organização.
- `vm_approve_quote(p_token uuid) RETURNS TABLE(order_id uuid, tracking_token uuid, tracking_expires_at timestamptz, status text, accepted_at timestamptz)`. `anon` e `authenticated`; capability válida cria um único pedido pendente usando snapshots congelados. Repetição retorna o mesmo pedido e capability; não registra pagamento, não inicia produção e não consome material.
- `vm_get_quote(p_token uuid) RETURNS jsonb`. `anon` e `authenticated`; retorna projeção pública allowlist do orçamento por capability aleatória, ou `NULL` para token inválido. Pode incluir marca, itens/preços, prazos, termos, notas públicas e status; exclui PII de contato, IDs internos, notas/custos/receita internos e credenciais.

## Acompanhamento

- `vm_issue_tracking(p_organization_id uuid, p_order_id uuid, p_expires_at timestamptz, p_nonce uuid DEFAULT NULL) RETURNS TABLE(tracking_id uuid, tracking_token uuid, expires_at timestamptz)`. Apenas owner/admin/finance autenticados; emite capability para pedido autorizado.
- `vm_revoke_tracking(p_organization_id uuid, p_tracking_token uuid, p_nonce uuid DEFAULT NULL) RETURNS TABLE(tracking_id uuid, revoked_at timestamptz)`. Apenas owner/admin/finance autenticados; recebe o token ativo e revoga essa capability.
- `vm_get_tracking(p_token uuid) RETURNS jsonb`. `anon` e `authenticated`; capability vigente e não revogada retorna somente `brand`, `code`, `title`, `status`, `status_version`, datas do pedido/produção/entrega, `expires_at` e histórico allowlisted (`status`, `status_version`, `created_at`). Não retorna capability, itens, preços, notas públicas/internas, termos, contatos ou valores/custos.
- `vm_get_order_tracking(p_organization_id uuid, p_order_id uuid) RETURNS TABLE(tracking_token uuid, expires_at timestamptz)`. Exige identidade JWT `authenticated` e papel organizacional owner/admin/finance no banco; viewers, production, anon e outras organizações são negados por `42501`. Retorna somente capability corrente, não revogada/não expirada do pedido e organização autorizados.

As rotas consumidoras devem evitar indexação e não colocar capabilities ou dados comerciais em analytics. As migrations foram aplicadas e os grants das RPCs administrativas foram verificados no projeto Supabase; detalhes e limites estão em `docs/public-sales-verification.md`. QA local e catálogo de funções no PostgreSQL não comprovam, por si, chamada de PostgREST pela UI, entrega WebSocket/Realtime no navegador ou publicação.
